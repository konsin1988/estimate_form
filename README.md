# Форма сбора прогнозов

Форма предназначена для ежемесячного внесения прогнозов по выручке и по затратам в соответствующих ЦФО.

> Форма имеет три вкладки: Выручка, Затраты и УП. Управление персоналом выделено в отдельную группу, так как их прогнозы по затратам четко делятся по ЦФО (в отличии от других ЦФО, которые не делят прогноз по затратам по ЦФО


```
- Сохранение в форме осуществляется по клику на кнопку "Сохранить данные". 
- Самари по месяцам, по ЦФО или подгуппам (где они присутствуют) осуществляется полностью автоматически.
- Возможность свернуть/развернуть все ЦФО/подгруппы по одной кнопке
```

### Стек
Для написания данного сервиса использовались следующие технологии: 

##### Клиент - React JS / TypeScript / Vite

##### Сервер - Python3 / Django 

##### База данных - Postgresql 15

##### Ежемесячное обновление данных / Рассылка по представителям ЦФО  - Airflow 3

##### Контейнеризация - Docker 

### Предпосылки появления: 
- Неудобство сбора информации с разных ЦФО
- Формирование единой базы прогнозов
- Отсутсвие последних данных у руководителей для принятия решений

### ...Немного истории
> Первоначально на клиенте был использован Redux для сохранение "как в Гугл документах", автоматически, без участия пользорвателя. Но такой подход с ростом количества пользователей (и в особенности администраторов, у кого есть полный доступ ко всем данным и ко всем ЦФО) оказался не подходящим для системы, где важна точность и безошибочность. 


### Рассылка
> Осуществляется два раза в месяц, по всем представителям. Предусмотрено остутствие дублирования писем для тех представителей ЦФО, у которых есть доступ как к выручке, так и к затратам, а также для тех, у кого ЦФО несколько. 

### Логирование
> Для контроля заполнения таблиц представителями ЦФО продумано логирование при посещение страницы, при сохранении данных. При этом продуман контроль над объёмом данных в таблице, сохраняется только последнее посещение человека в текущем месяце. Такой подход не сделает избыточное логирование, при этом даст возможным отследить, кто в какой момент вносил изменения.
